# Частное техническое задание: подсистема черновиков

Версия 1.0 · 16.11.2026 · Статус: на согласовании у автора канала; реализовано, кроме пунктов с пометкой «план»

Документ дополняет [требования MVP-1](mvp1-requirements.md) (публикатор и монитор) и описывает, как черновики попадают в очередь: от ИИ-автора до вето автора канала. Структура упрощена по мотивам ГОСТ 34.602.

## 1. Общие сведения

| Параметр | Значение |
| --- | --- |
| Система | MyWay · автопостинг Telegram-канала «Мой путь к финансовой свободе» |
| Подсистема | Черновики: приём, автопланирование, иллюстрации, вето |
| Заказчик | Автор канала |
| Исполнитель | Аналитик/разработчик проекта |
| Платформа | n8n Cloud, PostgreSQL (Neon), Telegram Bot API, Pollinations (генерация изображений), Claude (ИИ-автор) |
| Связанные документы | [vision.md](vision.md), [mvp1-requirements.md](mvp1-requirements.md), [BPMN TO BE](../bpmn/to_be.png), [UML](../uml/), [OpenAPI](../api/openapi.yaml), [тест-кейсы](../testing/test-cases.md) |

## 2. Назначение и цели

**Назначение:** без участия автора поддерживать в очереди 1 пост в день, оставив автору право отменить любой пост до публикации.

**Цели и метрики:**

| Цель | Метрика | Целевое значение |
| --- | --- | --- |
| Канал не простаивает | Дней из ближайших 7 с запланированным постом | ≥ 4 из 7 (иначе предупреждение в сводке) |
| Минимум ручной работы | Действий автора на один пост | 0 (по умолчанию пост выходит), 1 нажатие для отмены |
| Посты с визуалом | Доля новых постов с иллюстрацией | ≥ 90% (сбой генерации допускается, пост выходит текстом) |
| Нет перегруза ленты | Постов в день | ≤ 1 |

## 3. Характеристика процесса

**AS IS (до проекта):** черновики готовились вручную с помощью бота на ПК автора, очередь хранилась в SQLite на ПК. При выключенном ПК посты не выходили.

**TO BE:** ИИ-автор дважды в день проверяет очередь и при необходимости готовит один черновик. Подсистема сохраняет его, сама выбирает время, рисует иллюстрацию и присылает автору превью. Автор ничего не делает или нажимает «Отменить». Процесс показан на [BPMN TO BE](../bpmn/to_be.png) и [диаграмме последовательности](../uml/sequence-draft-intake.png).

## 4. Роли

| Роль | Кто | Описание |
| --- | --- | --- |
| Автор канала | Владелец канала (один Telegram ID) | Получает превью, отменяет или одобряет черновики, смотрит очередь |
| ИИ-автор | Запланированная задача Claude | Выбирает тему, пишет текст и описание иллюстрации, отправляет черновик |
| Система | Сценарии n8n | Сохраняет, планирует, генерирует, публикует, уведомляет |
| Подписчик | Читатели Telegram и Дзена | Получают опубликованный пост |

Права ролей: [матрица прав](../uml/use-case.md#матрица-прав).

## 5. Функциональные требования

### 5.1. Приём черновика

| ID | Требование |
| --- | --- |
| ФТ-01 | Система принимает от 1 до 10 черновиков за запрос в формате JSON (контракт — [OpenAPI](../api/openapi.yaml)). |
| ФТ-02 | Обязательное поле — `body` (непустой текст). Черновик без `body` пропускается, остальные из запроса обрабатываются. |
| ФТ-03 | Поле `type` принимает `news`, `plan`, `manual`. Любое другое значение заменяется на `news`. |
| ФТ-04 | Каждый принятый черновик сохраняется в `posts` со статусом `draft` до любых других действий, чтобы сбой на следующих шагах не терял текст. |
| ФТ-05 | Поля `source_url` и `image_prompt` необязательны; пустой `source_url` сохраняется как NULL. |

### 5.2. Автопланирование

| ID | Требование |
| --- | --- |
| ФТ-06 | Система ищет ближайший свободный день: на нём нет поста в статусах `approved`, `publishing`, `published`. |
| ФТ-07 | Время слота: `news` — 12:00 МСК, `plan` и `manual` — 19:05 МСК. |
| ФТ-08 | Горизонт поиска: `news` — сегодня и 2 следующих дня (новость устаревает), `plan`/`manual` — 14 дней. |
| ФТ-09 | Слот должен быть не раньше чем через 60 минут от текущего момента, чтобы автор успел увидеть превью. |
| ФТ-10 | Если слот найден — статус `approved`, заполнен `scheduled_at`. Если не найден — черновик остаётся `draft` и уходит автору на ручное решение (ФТ-17). |

### 5.3. Иллюстрация

| ID | Требование |
| --- | --- |
| ФТ-11 | По `image_prompt` (английский, 1–2 предложения) система генерирует изображение 1280×720 без текста на картинке. Пустой `image_prompt` — нейтральная иллюстрация на тему личных финансов. |
| ФТ-12 | `seed` генерации = ID поста, чтобы картинку можно было воспроизвести по той же ссылке. |
| ФТ-13 | Изображение отправляется автору в превью; `file_id` фото из ответа Telegram сохраняется в `posts.photo_file_id`, ссылка — в `posts.image_url`. |
| ФТ-14 | Сбой генерации не прерывает обработку: черновик планируется и публикуется без картинки, автор видит пометку в превью. |
| ФТ-15 | Формат публикации: текст ≤ 1000 знаков и есть фото → фото с подписью; текст > 1000 знаков и есть `image_url` → текст со скрытой ссылкой на картинку (крупное превью); иначе → текст. |

### 5.4. Превью и вето автора

| ID | Требование |
| --- | --- |
| ФТ-16 | Для запланированного черновика автору приходит превью: дата и время выхода, текст, картинка, кнопка «🚫 Отменить». |
| ФТ-17 | Для незапланированного черновика — превью с кнопками «✅ В ближайший слот» и «🗑 Удалить». |
| ФТ-18 | «Отменить» переводит пост в `cancelled`, если он `draft` или `approved` с `scheduled_at` в будущем. Для уже опубликованного, публикуемого или отменённого поста — сообщение «уже опубликован или отменён раньше», статус не меняется. |
| ФТ-19 | «В ближайший слот» планирует черновик по правилам ФТ-06–ФТ-07 с горизонтом 60 дней и слотом не раньше чем через 10 минут (автор сам принимает решение, ждать превью не нужно). |
| ФТ-20 | Команда `/queue` показывает автору очередь на ближайшие дни. |
| ФТ-21 | Пульт реагирует только на сообщения и нажатия от Telegram ID автора; остальные игнорируются. |

### 5.5. ИИ-автор

| ID | Требование |
| --- | --- |
| ФТ-22 | Запуск дважды в день: 08:45 и 16:45 МСК. Не больше одного черновика за запуск. |
| ФТ-23 | Решение о типе: сегодня или завтра нет поста → `news`; ближайшие 2 дня заняты, но в 7 днях есть свободный → `plan`; неделя заполнена → черновик не готовится. |
| ФТ-24 | Тема новости — самая просматриваемая за 24–48 часов в 6 заданных публичных каналах, факты проверяются минимум по 2 источникам. |
| ФТ-25 | Текст ≤ 950 знаков, первая строка — заголовок ≤ 120 знаков (на Дзене становится названием), без символов `<`, `>`, `&`. |
| ФТ-26 | ИИ-автор только читает БД (SELECT) и не может публиковать напрямую: единственный путь в канал — через очередь и вето автора. |

## 6. Нефункциональные требования

| ID | Требование |
| --- | --- |
| НФТ-01 | Превью приходит автору не позднее 3 минут после приёма черновика (генерация картинки — до 120 с). |
| НФТ-02 | Бесплатный лимит генератора — 1 изображение в 45 с; пакетная генерация идёт с паузой 50 с между картинками. |
| НФТ-03 | Ошибка любого сценария попадает в «Монитор» и приходит автору сообщением. |
| НФТ-04 | Токены и пароли — только в Credentials n8n; в репозитории ID и секреты заменены заглушками. |
| НФТ-05 | План: вход в API приёма защищён заголовком `X-API-Key` (сейчас вызов идёт только через авторизованный MCP-доступ к n8n, публичный адрес не активирован). |
| НФТ-06 | Время в БД — UTC, в сообщениях автору — МСК. |

## 7. Ограничения и допущения

- Подпись к фото в Telegram ограничена 1024 знаками — отсюда лимиты ФТ-15 и ФТ-25.
- У Дзена нет API для публикации; посты переходят туда через официальный кросспостинг из Telegram, поэтому формат поста подбирается под Telegram.
- Бесплатный генератор может выдавать картинки среднего качества; при росте требований — ключ Pollinations или другой сервис без изменения контракта.

## 8. Контроль и приёмка

Приёмка — по [тест-кейсам](../testing/test-cases.md). Подсистема принята, если все кейсы с приоритетом «высокий» пройдены, а остальные пройдены или имеют согласованное с автором обходное решение. Результаты фиксируются в [протоколе приёмки](../testing/acceptance-protocol.md).

## 9. Открытые вопросы

- Нужна ли автору правка текста черновика прямо из Telegram (сейчас — только отмена и повторная генерация)?
- Переносить ли картинку над текстом для длинных постов (требует прямого вызова Telegram API с параметром `link_preview_options`)?
